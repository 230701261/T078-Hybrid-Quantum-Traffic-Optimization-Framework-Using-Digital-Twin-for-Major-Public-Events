# Dynamic Traffic Control Implementation Plan

## Inspection scope

Reviewed the current repository tree, route/config inputs, paired SUMO/TraCI controllers, Digital Twin REST/WebSocket server, Quantum integration contracts and validators, operator UI, tests, and existing audit evidence in `Audit/`. The repository already contains uncommitted work; this plan preserves it. The inspected runtime status is based on current code plus dated audit evidence, not inferred from UI labels.

## Current end-to-end architecture

- The FastAPI server starts two isolated, real SUMO/TraCI sessions through `SimulationPair`: a classical baseline and an optimized context. Both receive the same scenario, density, seed, and current operator inputs.
- The UI loads static SUMO geometry from `/api/network/geometry`, receives both sessions' telemetry through `/ws/simulation`, and sends operator actions to existing REST endpoints.
- Density changes are validated and applied by scaling the active scenario's existing route-file `flow`/`personFlow` rates into a temporary route file before SUMO starts. Speed is sent to both controllers and changes real-time stepping.
- Route controls currently use configured logical corridors from `python/integration/id_mapper.py`, modify lane permissions and adapted travel costs, and attempt live vehicle rerouting. A scheduled-flow intersection causes a pre-mutation rejection for block requests. The audit confirms that this safe rejection prevents SUMO failure; full flow diversion/closure is not implemented.
- Signal changes currently accept logical junction mappings and rewrite durations of the loaded complete TLS program by phase color. Live readback detects unsupported phase classes; the audit confirms the current J4 program cannot represent independent red timing.
- Weather, VIP, and construction inputs are carried into both simulation contexts and the optimization payload. The controller currently applies configured speed factors, route costs, and corridor speed caps; these are simplified operational models, not native SUMO weather, VIP vehicle dispatch, or construction closure.
- The optimization trigger calls the Quantum client, validates 18-bit results and mapped IDs, and applies accepted actions through the TraCI adapter; the existing Classical fallback is used when the API is unavailable. The repository abstraction reports local-memory mode unless Supabase credentials are configured.
- The browser updates operational telemetry from WebSocket frames and optimization lifecycle/status; operation event history is exposed at `/api/operations/events` and embedded in telemetry.

## Implementation sequence

1. Preserve the safe flow-conflict rejection and current Quantum/QAOA, paired simulation, and UI shell.
2. Centralize discovered network/operator metadata and current constraint state; expose read-only routes, edges, signals, traffic capabilities and operator state.
3. Add structured, transactional operations with validation, snapshots, actual TraCI readback, rollback, and operation events. Keep unsupported full closure/red timing explicitly rejected where current SUMO configuration cannot safely support them.
4. Make the existing UI consume server metadata/state and display truthful operation outcomes; do not add client-generated success state.
5. Extend focused automated tests, run current unit/integration/live checks, then perform available browser and live SUMO/Quantum checks.
6. Generate the requested validation reports from observed results. Report absent Supabase credentials as a configuration blocker; do not fabricate credentials or cloud evidence.

## Explicit current limitations to retain until disproven by live tests

- Full corridor closure is currently preflight-rejected when scheduled flows use the corridor. The audit evidence says direct closure can invalidate flows and terminate SUMO.
- The tested J4 traffic-light program cannot represent independent red timing; the API must continue to report that as unsupported unless live program discovery proves otherwise.
- Supabase is not configured in the current documented environment; this work must not report a cloud transaction without credentials and database readback.
- Existing weather/VIP/construction controls are simplified SUMO speed/cost controls; current evidence does not prove native weather, explicit VIP vehicle dispatch, construction closure, or comprehensive constraint enforcement by both optimizer paths.
